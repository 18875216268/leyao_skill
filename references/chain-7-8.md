# 执行收尾阶段（chain-7-8）：7 执行复核交付（7a/7b/7c）→ 8 任务级复盘

> 总览与两门判据见 `references/chain-overview.md`。本页承载执行收尾阶段各步**执行详述**（含 7 拆分子步的入口与出口判据）。

## 7a. 执行与证据收集

每个 Task/Deliverable 创建独立 Run，按第 6 步执行计划逐条执行。原始数据只读进入 `raw`，清洗进入 `clean`，分析进入 `analysis`，结果先进入 `pending-review`（未过四门不得 confirmed）。**状态变更前记 checkpoint**（防崩溃后重复执行产生重复副作用，落点遵循第 6 步检查点规则）。

**执行中错误处置**：先按第 4 步失败策略分级处理（自纠正 → 降级 → 升级）；策略耗尽（升级层仍失败）→ 启动「阶段回环」按根因回退（结构化归因，不拍脑袋）；deviation low/medium 原步内处理，high 阻断回退。

**证据出口（7a 判据）**：Run 执行完成 + 中间产物落区 + checkpoint 记录齐备（每次状态变更有痕）；不可逆动作（外发/覆盖/删除）已后置且前置确认要求满足。

## 7b. 四门复核

对 7a 证据做独立复核，四门全过才可交付：
- **意图门**：对照 intent anchor（本轮明确需求，防 scope creep）；
- **数据门**：raw/clean 来源正确、清洗无损（对比行数/缺失率，对照过程检查）；
- **计算门**：指标口径校验用 `resolve --need-type caliber`（卡点调度），杜绝口径算错；
- **交付门**：用 intent anchor 的 `acceptance` 验收标准**逐项检查**（第 2 步定义 → 7b 执行，闭环）。

**内审准则（独立评估者视角 · 交付前主动自查）**：四门检查时切换到独立评估者视角自审——对照 `acceptance` 逐条自证（非走过场）、主动找茬不自辩；计算门用确定性对比（`resolve caliber` 对上期口径）；高价值/主观门交付可请求监督层抽样复核。分工：内审在交付前主动自查，失败策略在出错后处置，偏差记录在执行中——三者不重叠。

**复核出口（7b 判据）**：四门判定明确——全过 → 7c；任一不过 → 按「阶段回环」根因映射回退（交付门 → 2 步补验收；计算门 → 2 步补口径；数据门 → 1 步重建包；执行证据缺失 → 回 7a 补证据）。

## 7c. 交付确认

四门全过后交付：结果 `confirmed` → 交付 `delivered`；**覆盖/删除/移动/联网/登录/外发/关键公式范围模板映射改变**必须前置确认（安全不变量）；交付物写入 deliverable 注册中心。交付后转第 8 步复盘。

## 8. 任务级复盘（收尾 · 交付后必做）

交付完成后执行**复盘四问**（把本任务作为一次学习样本，不是重复执行；同样接受自我进化监督及其它治理层）：

1. **有效方法**：哪些步骤的方法/流程有效、可复用？→ 提炼为 `workflow`；
2. **浪费/教训**：哪些环节返工/低效/出错？→ 提炼为 `lesson`（反例护栏）；
3. **质量与反馈**：四门结果 + 用户反馈（K10）+ 隐式信号（**同一问题被反复提问 = 可能不满**）→ 标记待优化项；
4. **复用沉淀**：下次同类任务的改进点 + 可复用模板/口径 → 更新对应资产。

**反思准则（不自辩 · 教训过具体性门）**：复盘结论不自辩（不找借口）；每条教训须过**具体性门三判据**才可进入结论三验证——①**落到步**（作用于哪个环节：理解/规划/执行/复盘）②**落到判据**（该用什么判据而没用/误用）③**落到信号**（判据出现什么现象/阈值就该触发——让教训可被**看见**而非被**想起**）；过不了具体性门 = 空洞教训 → 仅记 episodic，不进 learn 沉淀。复盘本身接受监督评估，低质复盘不沉淀（见沉淀路径）。与内审准则分工：内审在交付前自查质量，反思在交付后提炼改进——不同时点不重叠。

**结论三验证（具体性门后必过 · 防伪规律污染知识库）**：教训先过具体性门（可执行）再过三验证（可信）——双门一前一后；复盘得出的规律/教训，须过三验证才可沉淀：
① **不落偶然**——结论落脚在偶然因素上 = 错（须到流程/制度层面，偶然事件无复用价值）；
② **指向事不指向人**——结论指向人 = 复盘未到位（人是变量，规律须从事物本质提炼）；
③ **交叉验证**——孤证不定案（结论须经其它事件/数据佐证，至少自洽于本任务全证据链）。
三验证任一不过 → 该结论仅记 episodic 事件，**不进入 learn 沉淀**（防"越复盘越错"）。

**沉淀路径（全治理层接管，非裸写）**：
- 复盘结论 → `supervisor.py record --type review --note "<复盘摘要>"` 入 episodic（**不可变事件**，供监督层跨 Run 评估）；
- 提炼的 workflow/lesson → `python brf/brf.py learn --problem "<复盘主题>" --answer "<有效方法>" --need-type process --trust reference --work-dir <dir>`（personal/shared 分流；L1/L2 自动审批、L3 留提案——**接受监督审批治理**）；
- 反复被问的卡点（隐式不满）→ 该 cache 条目标记待复核，下次 resolve **跳过早停**重新解决；
- 复盘本身接受监督：跨 Run 评估复盘质量，低质复盘不沉淀（与 learn 验证门禁一致）。
