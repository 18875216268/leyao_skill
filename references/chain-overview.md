## 规划-资源循环（规划阶段 3-6 专有 · 缺资源不硬推）

规划前先盘点：已掌握资源能否支撑「规划全流程 → 执行全流程」？

规划中如发现资源缺口（且非理解阶段可获得）→ **边规划边找资源**：能找到 → 按原规划继续；找不到 → 调整策略（换工具/换口径/降级/向用户确认）。循环直到所有资源到位、规划完全可行且可落地，才进入 7a 执行。

## 阶段方法论自学习（每步可外部学习方法论，让每一步标准化）

任一步自我评估「本步方法论不熟练」→ 走「外援路径」第 2 级（外部方法论学习）→ `learn` 沉淀 → 下次该步 K1/池直接命中，每一步随使用越来越标准化。

## 外援路径（不确定时 · 通用求助分级 · 横切总则）

任意环节出现"不确定 / 内部无法解决"（知识、口径、方法论、工具、资源、流程），先自问"内部能否解决"，不能则按级求助。**外援即求索，进入前先完成提取**：外援路径是思考协议③"先取后求"中求索一侧的落地——求助前先完成可及范围盘点（提取），提取确认无货才逐级外求；范围归属以盘点结果为准，不以主观印象定夺：
1. **内部知识**：卡点调度 BRF（三阶段：K1 → 注入‖会话并行 → 云智库（外部源）→ 网络引导）；
2. **外部方法论**：按 `brf/references/network-guidance.md` 多渠道学习（GitHub / 官方 skill 市场 / 权威站 / 必应）→ 蒸馏为 workflow/lesson/skill → `learn` 沉淀 → 下次内部直接命中；
3. **本机工具**：`tools_discovery` 动态发现（零注册零绑定，技能放进 `~/.workbuddy/skills/` 即被找到）；
4. **仍不确定**：暂停 → 向用户确认，或走「阶段回环」按根因回退。

**沉淀义务**：见主文档 1.2——本页不重复，只做分级统领与指针（各环节具体调用：卡点调度 / 方法论自学习 / 资源门 / 失败策略升级）。

## 思考协议（判断前的心智路径 · 横切总则）

**任何判断（分类/口径/选型/流程/验收/纠错）前按五步走通心智**——不是流水线而是闭环：任一步发现新信息都可推翻前一步结论。每步只给"想什么"，机制落地见指针：

1. **假设先行**——基于已有线索先形成可能答案（哪怕不完整）：有假设才知道找什么证据、验什么、补什么。自问"基于现有信息，我最合理的推测是什么？它解释了哪些、没解释哪些？"
2. **完整性核验**——检验信息集闭合：有没有没读的部分？汇总=明细？多源一致？（四判据见 `chain-0-2.md` 第 1 步「材料完整性核验」）
3. **知识查证**——先调用可及知识再下结论，不凭固有印象裸判。**知识动作先取后求**：一切"获取知识"的动作（指令引用 / 判断需要 / 执行需要）只有两个方向——**提取**（可及范围内已有：本地记忆 / 注入池 / 会话池 / 历史 / 方法论，直接取用）与**求索**（范围内没有，向外学习）。顺序判据：**提取优先，求索次之；求索前先证明提取失败**。**提取的判据（检索命中 ≠ 提取完成）**：①**盘点全集**——该主题相关条目全列出再选，检索用**宽词主题词**、结果**全集消费**（不取 top-1 单条）；②**核对适用对象**——条目的适用对象与任务主体匹配才取，不匹配即弃（标题像也没用）。自问"我**取过**没有？"——不是"我找到没有"；范围归属是盘点后的结论，不是盘点前的前提，"感觉像外部/通用"不构成跳过盘点的理由。
4. **变量分层**——区分"影响结果的关键变量"与"无关标签"：该信息**变了结果会变吗**？不会 → 标签，忽略不纠结。自问"这个信息影响最终结果，还是只是描述？"
5. **最小确认**——确认是最后手段：前四步仍不确定才问，且说明"已推过什么、已查过什么、只差哪一项"——让确认成为填空而非问卷（澄清优先级见 `chain-0-2.md`「歧义消解」）。

**思考预算（难度路由 · 防协议拖慢简单任务）**：先估难度再分配思考深度；档位**可升不可降**——执行中发现缺口/后果升级 → 升档不硬撑。难度四信号：信息完整度 / 歧义度 / 后果度 / 复用度。
- **快判档**：信息足 + 低歧义 + 低后果 + 常规 → 单遍推理（对应总则"简单事快速过"）；
- **标准档**：有歧义但可自解 → 走完整五步（自主解决上限）；
- **深度档**：高后果 / 高歧义 / 高复用 → 多轮假设-核验-查证循环，产出前自查，可请求监督层抽样复核。

## 知识前置（思考协议第③步机制 · 分级预载 · 横切总则）

**任何判断（分类/口径/选型/流程/验收/纠错）先检索可及知识，再下结论**——不凭模型固有知识裸判；读不到才按需求助（卡点调度/外援）。本节点明思考协议第③步（知识查证）的机制落地。**触发双通道**：①判断密度（按判断复杂度决定预载深度）②**知识动作触发**——指令含"参考/依据/按…/需要"等知识引用意图时，以引用对象为 key 走三源检索（本地 K1 / 注入池 / 会话池），完成"先取后求"的范围盘点，再决定提取或求索。预载分级（判断密度决定，非全量）：

- **常驻核心**（每轮）：总则/红线/主链骨架（SKILL.md）；
- **阶段预载**（进阶段读，摘要/top-k 级，不载全量）：理解阶段（0-2）→ 本地 K1（core 偏好 + 近期相似）+ 云端两库（注入/会话）+ ask-log 历史；规划阶段（3a-6）→ core 偏好 + procedure 工作流；
- **按需**（盲区）：卡点调度 BRF（三阶段含注入/会话/云智库）；
- **出错回载**（7a-7c 出错/偏差）：episodic 近期修正案例 + procedure。

成本三锁：相关性筛选（只预载判断高相关切片）· 摘要/索引级（top-k 片段+评分，不载全文）· 上下文护栏兜底（API 20 次/Token 50k）。**本地 + 云端两库一起读**——本地无的知识，云端注入/会话池可能有（对齐阶段 1「本地 K1 ‖ 云端注入/会话」）。

## AMD 分层注入触发点（记忆区 → 主链消费）

- 理解阶段（0-2 步）：进入前预载 `k1_inject`（core 用户偏好分区 + 近期相似问历史）**+ 云端两库**（注入/会话）→ 喂分类判断与需求确认（见「知识前置」）；
- 重规划阶段（3a-6 步）：进入前注入 `k1_inject proactive`（core 用户偏好分区，按 need_type 粗筛：caliber→caliber: 分区 / process|tool→tool:+caliber: / 其余全分区 + procedure 工作流）→ 喂流程感知与双准绳；
- 执行阶段（7a-7c 步）出错/复核偏差时：`k1_inject reactive` → 注入 episodic 近期修正案例 + procedure 参考，避免重蹈覆辙；
- resolve 的 K1 层：process/tool 诉求自动按 `kind=procedure` 检索「怎么做」（程序环原生接入）。
