# 治理平面（governance）：横切主链的卡点调度 · 阶段回环 · 实时控制 · 自我进化监督

> 治理平面不属于主执行链的普通步骤，横切全程。BRF 子系统同样以横切方式接入（内部自治，修改其内部不影响主 skill）。

## 卡点调度（BRF 横切）

主执行链任意阶段遇到：不懂的业务名词/不确定的指标口径/缺少制度或方法论依据/需要模板或数据基准 → 暂停当前步骤，调用 BRF 子系统 `python brf/brf.py ask --problem "<问题>" --work-dir <dir>`（计算门做口径校验时用 `resolve --need-type caliber`），取 `possibilities`/`best` 后继续；未解决（`ok:false`）则转用户确认。BRF 内部机制（三阶段调度 / 进化闭环 / 分层蒸馏）见 `references/brf-contract.md`。

## 阶段回环（横切 · 双向跨阶段交流）

主链并非纯串行：阶段间可**前向通知**（上游信息定向传给下游）与**反向回退**（下游失败按根因修正上游并重走）。与共享黑板互补：黑板被动全共享，回环定向主动消费。

### handoff 前向通知（上游 → 下游 · 契约驱动）

- 任意步骤出口做一次检查：本步获得的关键信息中，**本步用不到但某下游阶段要用的** → 记一条 handoff 到 `workspace-package.json` 的 `handoffs[]`：`{from_step, to_step, info, source_ref, confidence, status: pending}`（显式契约：谁传 / 给谁 / 传什么 / 依据 / 置信 / 状态）；
- 下游阶段入口先查「是否有给我的 handoff」→ 有则并入该步输入，消费后标 `consumed`（防重复注入）；复盘时评估未消费项：信息无用则标 `discarded`，有用则下轮修正通知规则；
- 例：第 1 步发现「数据源 A 权限可疑」→ handoff 给第 5 步（选型备 fallback）；第 2 步用户随口定「数值保留两位小数」→ handoff 给第 6 步（参数）与 7b（交付判据）；
- 边界：handoff 只传**信息**，不传任务/控制权（单 agent workflow，无多 agent 交接）；与 AMD 不重复——AMD 是记忆区→主链的纵向沉淀复用，handoff 是步骤→步骤的本轮内定向传递。

### rollback 按根因回退（下游 → 上游 · 结构化归因）

- 触发：执行/复核失败且第 4 步失败策略耗尽（升级层），或 deviation 判 high（阻断）；low/medium 仍在原步内处理，不回退；
- **回退三要素（触发前先过，缺一不贸然回退）**：①**定位**——能指出错在哪一步（结构边界=子步骤），定位不了先补证；②**置信**——根因映射证据充分、确属上游缺陷才回退，低置信先原步处理或补证（防"把对的改成错的"）；③**等待**——给足上下文再判定，不在信息不足时过早干预；
- **归因不用 LLM 拍脑袋**（LLM 自评归因仅 14% 准确率，怪最后一步是类别错误）——用四门失败类型 + deviation 证据做**确定性映射**定位根因阶段：

  | 失败特征（四门/证据） | 根因阶段 | 修正动作 | 重走范围 |
  |---|---|---|---|
  | 交付门失败：acceptance 无对应判据 | 2 | 补验收标准、重签 sign-off | 3a-7c |
  | 计算门失败：口径与上期不一致 | 2 | `resolve --need-type caliber` 补口径 | 3a-7c |
  | 数据门失败：角色/材料误判 | 1 | 重建 workspace-package | 2-7c |
  | Task 结构/粒度不过 | 3b | 重跑拆解四步 | 3c-7c |
  | 依赖环/validation 缺失 | 3c | 重排依赖/补验证点 | 4-7c |
  | 流程模式/数据流断链 | 4 | 重声明模式/补 output_id | 5-7c |
  | 工具不可用/描述不清 | 5 | 换选型/补能力描述 | 6-7c |
  | 执行参数/路径错 | 6 | 改执行计划 | 7a-7c |
  | 执行证据缺失/执行中错 | 7a | 补证据/失败策略后重执行 | 7a-7c |

- **增量重走**：从根因阶段重走，该阶段及之后产物标记作废重生成；此前已确认且未受影响的产物保留——不全部重来；
- **防死循环**：同一 WorkOrder 回退上限 2 次，超限升级人工或新 WorkOrder；每次回退写 deviation（category=rollback，evidence=归因依据），审计可溯。

## 实时控制（双准绳监督）

当前 Run 建立 intent anchor；K0-K10 关键节点可写 checkpoint；输入 fingerprint 用于恢复。**双准绳监督**：deviation 先对照两条准绳——①**需求至上**：违背用户本轮明确需求（intent anchor）→ medium 暂停确认，涉及范围/关键映射/外发 → high 阻断；②**习惯为主**：违背用户长期习惯（core 记忆）→ 默认纠偏回习惯（用户本轮明确改变除外）。**实时记录用户信号**：K2 确认、K8 四门、K10 反馈及任意时刻的用户纠正 → `supervisor.py record --correction` 入 episodic。deviation low 可记录纠偏、medium 暂停确认、high 阻断；终态不可修改。偏差与用户修正经监督层跨 Run 评估 → 习惯提案 → core 沉淀 → 下次 Run 以 core 为准绳（实时控制 ↔ 监督 ↔ 记忆治理闭环）。

## 记忆职责边界（各司其职，不混用）

记忆区只做存储/检索/固化候选——不做偏差判断（实时控制）、不做审批裁决（监督）、不做进化评分决策（BRF）、不驱动执行（主链/调度师）。**写入单一通道**：episodic 经 `record`，semantic/core 经监督审批（唯一审批权）；**评估单一真源**：进化评分归 BRF、L1/L2/L3 分级归监督、偏差分级归实时控制；**存储不越权**：控制/监督/BRF 一律走记忆区接口，不自建存储。详见 `references/memory-and-supervision.md`。
