# 交付物内容规范（reporting）：报告 / 复盘怎么写

> 职责边界：本页承载**内容层规范**（报告/复盘类交付物怎么写、结构如何）；对象结构（kind/type/period 字段、注册）见 `references/domain-model.md`；复盘**机制**（四问/结论三验证/沉淀路径）见 `references/chain-7-8.md`。三者互补不重复。

## 一、通用汇报原则（所有报告/复盘类交付物）

1. **结论先行**（金字塔原理）：开头第一句给核心结论/建议，再补支持要点——领导最想先听"这事怎么样了"。
2. **数据说话，不凭印象**：能量化的绝不形容（"完成 80%、比预期提前 3 天"而非"推进顺利"）；数据须可溯源。
3. **对齐目标，不罗列动作**：每条内容回答"对团队/业务目标有什么贡献"——10 件事不如 1 件事推动关键结果。
4. **给方案，不给难题**：带选项汇报（A/B 方案 + 倾向 + 理由），把决策请求前置。
5. **分层呈现**：概要（One-pager）→ 细节（附录/链接）——正文只放决策必要信息，深挖可追溯。

## 二、report 类模板（日报/周报/月报/季报/年报）

### 周报·三段式（日常节奏）
```text
1. 本周完成：结果 + 数据（对齐 OKR/里程碑）
2. 进行中：进度 + 卡点（量化差距 + 根因）
3. 下周计划：目标 + 需要的支持（决策/资源请求）
```

### 月报/季报·One-pager（高层汇报）
```text
1. 结论/建议（一句话，先给）
2. 目标回顾（对照期初目标）
3. 关键结果（数据对比：本期/环比/同比，前置-后置指标组合）
4. 亮点与不足（各 1-2 条，不凑数）
5. 偏差与根因（量化 + 根因，到流程/制度层）
6. 风险与预案（RYG 信号 + 阈值-触发-预案）
7. 下阶段重点（≤3 件要事）+ 明确决策请求
```

### 日报·极简
```text
今日产出（结论 + 数据）· 卡点/风险（需支持）· 明日计划
```

## 三、retrospective 类模板（品种/客户/专项复盘）

```text
1. 背景与目标（当初为什么做、期望结果）
2. 做了什么（过程叙述，给共同讨论基础）
3. 结果如何（务必量化，对照目标）
4. 经验与教训（复盘四问产出：有效方法/浪费教训/质量反馈）
5. 结论三验证（①不落偶然 ②指向事不指向人 ③交叉验证——机制见 chain-7-8）
6. 可复用方法论（workflow/lesson/口径 → learn 沉淀）
7. 下次行动（具体到人/时点/判据）
```

## 四、向上临时汇报·电梯式（SCQA，60-120 秒）

```text
S 情境（背景/目标一句话）→ C 冲突（当前阻力/变化）→ Q 问题（需决策什么）→ A 建议（方案+倾向+理由+请求）
```

## 五、模板应用规则

- 报告/复盘交付物生成时**按上述模板结构组织**（自由度分级：中档——给框架，内容模型即兴填充，不写死措辞）；
- 数据必可溯源（指标来源链接/口径标注）；结论必须来自四门已确认结果（不凭空）；
- 复盘类交付物**必须过结论三验证**后才可沉淀（防伪规律，见 chain-7-8）；
- 本规范是内容结构约定，不替代四门/内审等质量机制（机制见 chain-7-8）。
