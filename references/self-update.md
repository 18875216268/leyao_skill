# 自主更新（self-update）：独立维护层

> **定位（独立层，不混杂）**：本层是**独立维护层**——不属于主链(0-8)、BRF、治理、记忆任何一环，**不参与 skill 功能执行**，仅"方便使用"的系统自我维护。全程 **GitHub 公开 API**（`api.github.com` 读版本 + `codeload.github.com` 拉 zip）——**公共仓库匿名可读，任何使用者无需凭证/权限/配置**；只替换源码与文档，绝不触碰本地记忆/凭证/登录态/归档。

## 零、AI 快速使用（直接照做，无需分析）

```bash
python scripts/self_update.py auto
```

**后台静默启动、不等待**——自动完成：检查远端版本 → 有新版本自动拉取更新（校验递增→备份→原子替换→失败回滚）→ 报告结果。更新在后台完成、下次会话生效，不影响当前主任务。

- 返回"✅ 已是最新" → 直接继续主任务；
- 返回"✅ 已自动更新 X → Y" → 更新完成，下次会话生效；
- 网络不可用/未配置 → 直接跳过，不阻塞不报错。

## 一、更新机制（闭环 · 每次使用）

1. **检查**：`auto` 先读远端 `SKILL.md` 的 version（`api.github.com/contents`，匿名可读）对比本地；
2. **拉取**：有新版本 → `codeload.github.com/zip/refs/heads/main` 下载分支 zip（纯 API，匿名）；
3. **校验**：包内 SKILL.md 版本 **严格高于** 本地（防降级/防重复覆盖）；
4. **替换**：备份 → 原子替换（`os.replace`）→ 失败自动回滚；
5. **闭环**：AI 从返回三态得知"已最新/已更新/跳过"——没有最新则下次自动再拉，直到与远端一致。

**保护红线（apply 绝不覆盖）**：`.workbuddy/`（本地记忆/配置）、`.wrangler/`（云端登录态）、`leyou_token.json`、`wrangler-account.json`、`data.json.archive`、运行产物（.pyc）——只替换源码与文档。

## 二、发布流程（仅维护者/作者 · 使用者无需阅读）

1. 修改代码/文档 → 升 `SKILL.md` 的 `version`（如 12.3.4）；
2. 推送文件到仓库 main 分支（`git add . && git commit && git push`，或 API 上传）；
3. 使用者下次运行 `auto` 即自动拉取新版本——**无需发布 Release/tag**（branch 模式）；
4. 若改为 Release 模式：`self_update.json` 设 `"mode": "release"` 并创建 `v<version>` 的 Release。

## 三、不做什么

- 不覆盖本地任何数据/凭证/登录态（保护清单硬编码）；
- 不在任务执行中途强制重启（更新后下次会话生效）；
- 不自动降级（远端版本必须高于本地才允许替换）；
- 不需要任何使用者凭证/权限（公共仓库匿名 API）。
