# 流程、工具与业务操作

## 分层

```text
任务拆解 → 抽象流程（做什么） → 能力需求（需要什么）
→ 工具/技能/脚本/数据源绑定（用什么） → 可执行流程（如何落地）
```

抽象流程不绑定工具。工具契约包含 capabilities、inputs、outputs、速度、准确度、格式保真、审计性、网络需求、副作用、fallback 和验证项。未知副作用、联网、登录、覆盖、删除、外发一律需要确认。

**三层边界判据（防重复）**：第 4 步=逻辑层（换机器/换工具可原样复用，不出现工具名）；第 5 步=资源层（选型决策可复用，fallback 是工具级替代）；第 6 步=物理层（绑定本机环境，逐条映射第 4 步）。第 4 步失败策略只管流程级处置，与第 5 步 fallback 层级不同。

## 任务拆解（3a-3c）

原子 Task 四判据：单 Run 可完成 / 输入输出确定 / 可独立验收 / MECE 不重不漏。拆解自上而下：定交付物清单 → 反推顶层 Task（复用既有）→ 按能力拆到原子 → 依赖边 + 验证点。

`Task.validation` 激活门：仍为占位值（`Define validation before activation`）不得激活；**交付判据**引用 Intent Anchor 的 acceptance 对应条（7b 交付门检查），**过程检查**交第 4 步抽象流程细化。

执行中触发再规划（① 任务失败 ② 新信息 ③ 需求变化 ④ 资源约束 ⑤ 依赖阻塞）→ 先诊断（卡点调度/资源门）→ 局部调整（改依赖/补 Task/改验证）或重跑拆解四步；③ 回第 2 步重签 sign-off、④ 走规划-资源循环。再规划 = 阶段回退链的特例（根因在 3b/3c 时触发，见下）。

## 阶段回环

主链非纯串行，两向跨阶段交流：

**handoff 前向通知（上游 → 下游）**：步骤出口检查"本步用不到但下游要用"的关键信息 → 记 `workspace-package.json` 的 `handoffs[]`（from_step/to_step/info/source_ref/confidence/status）→ 下游入口定向消费（标 consumed）。只传信息不传控制权；与 AMD（纵向沉淀）互补不重复。

**rollback 按根因回退（下游 → 上游）**：失败且第 4 步失败策略耗尽或 deviation high → 用四门失败类型 + deviation 证据做确定性归因（不靠 LLM 猜，LLM 自评归因仅 14% 准确）→ 按定位表回根因阶段修正 → 增量重走（已确认不变产物保留）→ 同一 WorkOrder 回退上限 2 次，超限升级人工。每次回退写 deviation（category=rollback）。

## 工作包和模板

先识别工作包中的控制文件、数据、历史样例和候选模板，再读取所有 sheet/标题/表头/数据块/公式/合并单元格；生成模板指纹和字段映射，关键字段经确认后才填充副本。模板变化创建新映射版本，旧版保留。

## 数据操作

数据源优先为工作区文件和已登记能力；调用系统/API/技能前核对参数 schema。下载、全量/增量、日期覆盖、批次、行数和 checksum 写入 manifest。报错不等于零数据；分批合并后重新去重和聚合；缺失标待补。

清洗进入 `clean`，计算进入 `analysis`。比率不得相加：汇总率 = Σ分子 / Σ分母。目标拆分合计必须精确，尾差调末位。计算脚本和输入版本可复算。

## 交付

交付物先 stage 到 `pending-review`；四道门：意图、数据、计算、交付。全部通过才 confirmed/delivered。模板原件只读；输出路径必须 containment 在 work-dir；不直接执行 Office 渲染或外发。
